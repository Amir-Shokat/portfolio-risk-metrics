# Data and calendar

## Files

All CSV, UTF-8, ISO dates (`YYYY-MM-DD`).

| File | Columns | Notes |
|---|---|---|
| returns | `date,twr,status` | `twr` decimal; `status` is `ok` or `not_computed` (then `twr` is empty) |
| calendar | `date,session` | every calendar date, `open` or `closed` |
| risk-free | `date,ytm` or `date,ytm_percent` | the column name declares the unit |
| market (optional) | `date,return` | total-index daily return, for beta |

The files in [`examples/`](../examples) are synthetic and regenerated by
`scripts/make_example_data.py` with a fixed seed.

## Official calendar

The Tehran Stock Exchange trades Saturday to Wednesday and closes on public holidays of the
solar (Jalali) calendar and on lunar religious holidays, which move about 11 days earlier
each Gregorian year. The calendar file is the only source of truth for what a session is.

* Session counts (recovery duration, window coverage) come from the calendar, never from
  the number of rows a user happens to have.
* A session on which the investor did not trade is still a session.
* Holidays are not padded with zero returns. Padding would lower volatility and lengthen
  recovery.
* A return dated on a closed day, or on a date the calendar does not know, is invalid
  input. It usually means a timezone or cutoff problem upstream.

The example calendar uses approximate holidays and is not an official calendar.

## Missing, not computed, zero

These three are different and must stay different:

| Case | Example | Treatment |
|---|---|---|
| Genuine zero | portfolio unchanged that day | a valid observation, counted in N |
| `not_computed` | the return service could not define a return (e.g. opening capital below its minimum) | excluded from the sample, counted and reported; status unchanged |
| missing | a session with no row at all | blocks the whole window: `INCOMPLETE_COVERAGE` |

Replacing a missing return with zero is the single most common way to make risk look
smaller than it is.

## Risk-free series

* One quote per session, matched on the exact date.
* A missing quote is `RF_MISSING` for the metrics that read the risk-free series (downside
  deviation, Sharpe, Sortino, weekly ratios, beta) and only for those. Volatility and
  drawdown are unaffected.
* An unusable quote (non-numeric, at or below -100%) is `INVALID_INPUT`.
* No forward fill, no zero fill, no current rate applied to past dates.

## Return values

* Returns below -100% are invalid.
* Exactly -100% is a real total loss. Whether to show risk after it, and how to treat
  a later re-funding of the account, is an open decision, so it is `POLICY_PENDING`.
* Extreme but valid returns are kept and can be flagged for review; they are not trimmed.

## Contract violations

Some problems mean the file itself is broken. These raise `InputError` with a reason code
instead of producing any number: duplicate dates, unordered rows, unparseable dates or
numbers, an `ok` row without a value, a `not_computed` row with a value, an unknown session
flag, a missing column, and a risk-free file without a declared unit.
